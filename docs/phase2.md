# Phase 2: classical recommendation models

Phase 2 adds item-based collaborative filtering and implicit matrix factorization to the existing popularity benchmark. These are offline models; serving, neural retrieval, ranking and online experiments remain later phases.

## Shared protocol

All three models receive exactly the same global temporal training partition, positive threshold (rating >= 4), training catalog, evaluation users, K and seen-item filters. No negative sampling is performed. Validation and test scores are generated by frozen training weights and profiles. Test filtering excludes training and validation ratings, but validation preferences do not update either personalized model. This is a static-profile comparison, not a rolling online recommender.

The model interface accepts an explicit user ID, seen movie IDs and K. User profiles consist only of positive training ratings. All observed training items remain in the catalog, even if they have no positive ratings. New users and users with fewer than three positive training ratings fall back to popularity. This threshold is configurable. The report separates `warm` and `fallback_eligible` users using training positives, consistently across models. The older evaluator's `cold_start_users` field means no pre-evaluation history (train for validation, train+validation for test); it is distinct from absence of a fitted training profile.

## Item-based collaborative filtering

Let B be the binary user-item matrix of positive training ratings. Similarity for distinct items i,j is:

`cosine(i,j) * overlap(i,j) / (overlap(i,j) + shrinkage)`

where cosine is `overlap / sqrt(positive_count_i * positive_count_j)`. Self-similarity is zero. Each source item retains at most 100 neighbors, ordered by similarity then movie ID. This directed pruning is deliberate. A user's score is the sum of retained similarities from their positive training items; unrated movies with zero scores remain eligible. Final ties use training popularity then movie ID. Sparse 256-item co-occurrence blocks avoid a dense full item-item allocation, though common-item blocks can still be large on 32M.

## Implicit matrix factorization

The confidence-weighted ALS implementation minimizes:

`sum_ui c_ui * (p_ui - x_u dot y_i)^2 + lambda * (sum_u ||x_u||² + sum_i ||y_i||²)`

Here p=1 for positive training ratings and 0 elsewhere; c=1+alpha*p. Each alternating update solves the exact regularized normal equations, using the fixed-factor Gram matrix to account for all unobserved entries. Defaults are 32 factors, 12 iterations, alpha=20, lambda=0.1 and seed=42. Factors start from seeded Gaussian item vectors. Scores are factor dot products, with popularity and movie ID as deterministic tie-breakers.

This is a modeling transformation of explicit ratings, **not observed implicit clicks**. Missing and low-rated pairs both receive the lower-confidence zero preference; the model does not claim missing ratings are observed dislikes. No rating prediction/RMSE claim is made. The formulation follows [Hu, Koren and Volinsky (2008)](https://yifanhu.net/PUB/cf.pdf). Sparse operations use [SciPy CSR matrices](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csr_matrix.html).

## Selection, uncertainty and timing

One preconfigured candidate per family is fitted; no hyperparameter search is claimed. The selected model maximizes macro validation NDCG@K, with insertion order resolving exact ties. Selection is written before test evaluation. All models' test outcomes are reported, including negative differences.

For each model pair, rows are aligned by user ID and the same users are resampled together. The 95% percentile interval is computed from 1,000 bootstrap means of per-user treatment-minus-control differences. This is a paired offline comparison, conditional on this dataset, split and configuration. Intervals are exploratory, not adjusted for multiple metrics/model pairs, and do not establish online lift or a causal effect. Cohort metrics are descriptive point estimates; empty cohorts return null.

Training wall time, serialized artifact size, recommendation-call latency percentiles and sequential throughput are recorded. Recommendation-call timing includes scoring, sorting and seen filtering, but excludes evaluation metrics, network and API overhead. There is no concurrent load test. Single-thread BLAS environment settings improve repeatability; timings still vary with machine load.

## Artifacts and reproducibility

`python -m recsyslab.benchmark --output artifacts/phase2-1m` trains all models and creates:

- `metrics.json`: common metrics and cohort summaries for every model/split.
- `paired_comparisons.json`: paired differences for all three model pairs.
- `selection.json`: validation-based selection rule and chosen model.
- `{split}_{model}_per_user.csv`: paired-evaluation inputs; keep private/local.
- `item_cf/`, `implicit_als/`: schema-versioned JSON, numeric NPZ arrays, sparse profiles and similarities; no pickle loading.
- `popularity.json`: training catalog and counts.
- `manifest.json`: configuration, cutoffs, source/code/artifact hashes, runtime versions, training times, artifact sizes and thread settings.

Each persisted personalized model is loaded back and every training user's score vector is checked for exact equality before evaluation. Unit tests also refit on shuffled rows and check deterministic scores, verify the ALS update against a dense reference, and change held-out ratings while checking that fitted models remain identical. Run the full benchmark in a new output directory to independently verify repeatability. A second run should match model scores and non-timing metrics; compressed archive bytes may differ due to serialization metadata.

Source data and user-level artifacts remain ignored by Git. Only aggregate metrics, manifest and a written report are copied into `reports/phase2/`. Full 32M training is not scale-validated: Python ALS loops, sparse co-occurrence blocks and full-catalog sorting need profiling before that claim. Two-stage retrieval is intentionally reserved for Phase 3.
